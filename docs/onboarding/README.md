# Начало работы в Shertwg group

## Перед изменениями

1. Прочитайте `AGENTS.md`, `docs/CONTRACTS.md` и документацию изменяемого модуля.
2. Проверьте текущую ветку и `git status`; сохраните чужие локальные изменения.
3. Сверьте задачу с текущей реализацией: спецификация сама по себе не означает, что функция уже работает.

## Зоны проекта

- Общая основа и сервер: `src/core/**`, `server/**`, `tests/**`.
- Веб-чек-ин: `src/features/checkin/**`.
- Рекомендации и обратная связь: `src/features/actions/**`.
- Показатели и синтетические сценарии: `src/features/insights/**`, `src/demo/**`.
- Telegram-бот: `bot/**`; он взаимодействует с БД только через согласованный серверный API.

Сохраняйте текущие экспорты и props. Новые общие настройки, зависимости, типы и endpoint сначала согласуйте и задокументируйте.

## Данные и проверки

Используйте только синтетические сообщения, пока отдельно не согласованы правила согласия, хранения и отзыва для реальных данных. Полный состав участников обязателен; отказ, отзыв или неизвестный участник останавливают обработку. Не помещайте исходные тексты или секреты в логи, тестовые фикстуры и коммиты.

Запускайте проверки, относящиеся к изменению. Для веба и сервера: `npm run check` и `npm test`. Для Python: `python -m unittest discover -s bot/tests -v` и `python -m bot --check` из venv. В отчёте указывайте только реально выполненные проверки.

Каждую завершённую задачу оформляйте небольшим коммитом и merge request в `develop`. Не отправляйте напрямую в `main`/`develop` и не переписывайте чужую историю.
