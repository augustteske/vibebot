## Что нужно для переноса
Ссылка на пустой приватный проект в нужном GitLab либо адрес сервера и пространство владельца. Не присылать пароль или токен в чат; вход и Git-доступ настраивать обычным способом у себя.

После получения точного адреса:
1. Проверить проект и права.
2. Добавить отдельный remote gitlab; существующий origin сохранять до проверки переноса.
3. Загрузить main, develop и четыре feat-ветки без force-push.
4. Проверить ветки и pipeline.
5. Выбрать GitLab основным remote после проверки; обновить ссылки в README.
6. Выдать участникам Developer, Августу оставить Owner/Maintainer; приглашать только по точным логинам.
7. main и develop — изменения через merge request, интеграцию выполняет Август.

Готовый помощник для пустого проекта, выполнять из корня репозитория:
```powershell
./scripts/migrate-gitlab.ps1 -RepositoryUrl '<точный Clone URL из GitLab>'
```

Он проверяет пустоту проекта и пушит только шесть названных веток. При непустом проекте останавливается, чтобы сначала согласовать истории. Авторизация выполняется обычным Git; токены в скрипт не записываются.

## CI
Один job на Node.js 24: npm ci → npm test → npm run build. Готовая папка dist сохраняется как artifact на 7 дней. При открытом MR исключается дублирующий branch-pipeline. Запуск в GitLab пока не проверен: нужен проект с доступным runner.

GitLab Docs: https://docs.gitlab.com/ci/quick_start/
