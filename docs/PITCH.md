# Питч Vibee: Telegram v1 — демонстрация

## Подготовка

Нужны Node.js 24 и Python 3.12. Из корня репозитория:

```powershell
npm install
python -m pip install -r bot/requirements.txt
$env:NODE_ENV = "development"
$env:VIBEE_TELEGRAM_SYNTHETIC = "true"
$env:VIBEE_TELEGRAM_BOOTSTRAP_CREDENTIAL = (node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))")
npm run dev
```

Откройте http://127.0.0.1:5173. Для этого локального QA-режима сервер использует отдельную SQLite-базу в `.data` и включает только синтетический Telegram API. Создайте тестовое пространство: пока к нему не привязана тестовая группа, блок аналитики показывает «Нет активной привязки».

Во втором терминале можно запустить личный Telegram-демо-бот (нужен собственный токен BotFather):

```powershell
$env:TELEGRAM_BOT_TOKEN = "<локальный токен Telegram>"
python -m bot
```

Личный бот показывает `/start` и `/stop`; сам по себе он не подключает групповой чат к веб-аналитике. Без токена проверьте только загрузку обработчиков: `python -m bot --check`.

## Сценарий показа

Основной воспроизводимый цикл — автоматизированное синтетическое HTTP/SQLite-демо. В третьем терминале из корня проекта:

```sh
node --test --test-name-pattern="synthetic full cycle" tests/telegram-api.test.mjs
```

В терминале последовательно покажите:

1. **Привязка и согласия.** Тест создаёт изолированную синтетическую привязку; компания и все шесть вымышленных участников дают согласие. Обработка становится активной только после явного подтверждения.
2. **Приход сообщений.** Тест подаёт синтетические события, не читая Telegram. Период с 19 сообщениями остаётся `insufficient`, без опубликованных чисел.
3. **Калибровка.** Два допустимых закрытых периода на разных датах возвращают `calibrating`, метрики скрыты.
4. **Сводка.** После третьей пригодной даты сервер публикует только агрегаты: вне расписания — 25%, равномерность участия — 89.8%, распознанная лексика благодарности — 20%. `comparison` остаётся `null`.
5. **Рекомендация и обратная связь.** Сервер выдаёт шаблонную карточку с наблюдением, объяснением, ограничением и действием. Тест подтверждает шаг, закрывает два вида агрегированной обратной связи, затем отзывает согласие и проверяет паузу.

В веб-кабинете показывайте живое состояние без привязки — «Нет активной привязки». Публикуемые числа и карточка в этом сценарии видны в выводе теста; тест использует временную базу и не наполняет базу веб-кабинета.

## Что важно проговорить

- Полный цикл выше синтетический: он не подключается к Telegram и не доказывает обработку реальных сообщений.
- Личный polling-бот запускается отдельно. Реальная привязка групп, сбор согласий и получение групповых сообщений ещё не доступны как сквозной пользовательский сценарий; не добавляйте бота в рабочую группу для демонстрации.
- Для публикации нужно минимум пять авторов и 20 сообщений в каждом из трёх пригодных периодов на разных локальных датах. Демо-калибровка ускорена синтетическими часами, а не ожиданием трёх реальных дней.
- Метрики — агрегаты сообщений, не оценка нагрузки, вклада или психологической безопасности. Малые группы скрываются; абсолютная анонимность не обещается.
- Рекомендация — шаблон; внешний ИИ не подключён. Действия и отзывы не отправляются автоматически в Telegram.
- Синтетический режим разрешён только при `NODE_ENV=development` и аварийно завершается в остальных режимах. Не включайте его для реального окружения и не коммитьте токены или `.env`.
