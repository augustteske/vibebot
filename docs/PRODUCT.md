# VibeBot — продуктовая опора
VibeBot — веб-приложение с логикой бота: добровольные чек-ины, агрегированная температура команды и небольшие действия по ясности, поддержке и признанию. Слоган: «Почувствовать команду. Сделать следующий шаг».

## Ключевой сценарий
Три оценки 1..5 (ресурс, ясность, поддержка) → завершённый раунд с достаточным числом участников → объяснимое предложение → подтверждённая договорённость → проверка пользы.

Первая аудитория — команды разработчиков, особенно проектные и хакатонные. Гипотеза: понятный маленький шаг помогает начать полезный разговор. Эффект пока не измерен.

## Главный экран
Общий статус + лента VibeBot + чек-ин + принятый следующий шаг. У состояний есть текст, цвет не является единственным носителем смысла. У статистики — период и актуальность, у подсказки — основание. Максимум две инициативные карточки в день после подключения общего хранилища; откладывание/отказ.

## Карточки
1. Мало ясности → выбрать общую цель дня.
2. Мало ресурса → упростить, перенести или разделить одну задачу.
3. Трудно попросить поддержку → добровольный круг «нужна помощь / могу помочь».
4. По запросу или завершению этапа → конкретная благодарность.
5. По явному запросу автора → сообщение в форме «факт → влияние → просьба».

Первые три используют стартовый порог: >=40% низких ответов при достаточном участии. Благодарности доступны при любом размере команды. Правила и пороги требуют дальнейшей проверки.

## Приватность
Добровольное участие; минимум пять разных ответов; фиксированные раунды; отсутствие персональной истории настроений в UI; ограничение доступа и хранения. В реальной системе — серверная проверка. Четыре разработчика проекта не обходят порог ради демонстрации: используется явно вымышленная команда из шести человек. Проверку права участия отделяем от хранения ответов; границы гарантий описываем честно.

## Приоритеты
P0 к питчу: интерфейс, три вопроса, допустимые состояния, карточка ясности, подтверждение, последующий демо-отзыв, воспроизводимый 60-секундный показ.
P1 к финалу: общее сохранение, пространство и приглашение, проверки на сервере, обработка ошибок, настоящий ограниченный вызов ИИ при доступном провайдере.
P2 при запасе: благодарности, помощник формулировок, дополнительный полиш.
Интеграции с мессенджерами и обучение модели — дальнейшее развитие.

## Проверка пользы
Участие, принятие предложений, завершение договорённостей, агрегированная оценка полезности. Диагнозы, эффективность отдельных сотрудников и обещания уменьшения выгорания не выводятся. Честный сильный показ — полный цикл, а не неподтверждённые проценты улучшения.
