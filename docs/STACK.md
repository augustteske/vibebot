# Техническое решение — 31 октября 2026
## Фиксированный стек
- Веб: React + TypeScript + Vite.
- Сервер: Node.js 24 и текущий HTTP API. FastAPI не вводим.
- Данные: SQLite и существующее хранилище. PostgreSQL — возможная миграция после MVP при появлении требований.
- Telegram: отдельный Python 3.12 + aiogram 3.31.0 в bot/, отдельная ветка feat/ilian-bot.
- ИИ: планируем серверный Groq API с таймаутом, проверкой ответа и переходом на шаблон. Реального подключения пока нет; конкретная модель и квоты аккаунта требуют проверки.
- Разработка: GitLab, MR, npm run doctor, npm run check; отдельный Python-job CI.
- Запуск: обычный npm run dev или необязательный Docker Compose. Один веб-сервер и отдельный процесс бота; сеть микросервисов не строим.
- S3 пока не нужен: вложения и файлы не собираются. Локальная модель Ollama — возможный будущий провайдер, не текущая зависимость.

## Границы
React → Node API → SQLite.
Telegram → Python/aiogram → согласованный Node API (последняя стрелка ещё не реализована).
Node → Groq API (ещё не реализовано).
Бот не пишет в базу напрямую и не рассчитывает показатели, которые должен скрывать сервер.

## Два разных источника
Источник данных: чек-ин / утилита. В карточках предусмотрен будущий необязательный prop, имя и схема согласуются.
Источник генерации: ai / template. Сейчас реальные подсказки шаблонные, source='template'. Не выдавать демо и шаблоны за результаты ИИ.

## Принципы
Подключение корпоративного модуля — только с явным согласием компании и каждого участника. Понятный состав данных и отказ. Руководитель видит агрегаты закрытого периода при >=5 участниках, без авторства и личных сообщений. Никаких диагнозов или оценки отдельного человека. Чат-аналитика, риск-индикаторы и способы решения пока дорожная карта. До выбора метрик не заявлять, что они доказанно предсказывают конфликты.

## Согласовать до серверной интеграции
Новые endpoint и схемы фиксирует Август в CONTRACTS.md после согласования. Нужны компания/пространство, бот-авторизация, согласия и отзыв, связь участника с веб-идентичностью, защита от повторов, roundId, удаление и срок хранения. УТОЧНИТЬ: конкретные схемы и endpoint, состав будущих метрик, срок хранения сырых текстов, модель и квоты Groq.

## Docker
docker compose up --build web
Адрес: http://127.0.0.1:8787. SQLite и ключ сервера хранятся в named volume vibebot_data. Корневые .env и .data исключены из build context. Корневая .env не копируется в образ. Для внешнего размещения нужны HTTPS и соответствующие настройки; текущий порт опубликован только на loopback.
Конфигурация Compose проверяется без Docker engine, но сборка/запуск образов требуют запущенного Docker Desktop/Engine. Не считать контейнеры проверенными до фактического запуска.
