# Контракты v1 — командный сервер и демо
Обновлено 31 октября 2026 года. Питч в 12:00 по Омску. GitLab выбран основным хостингом исходников; перенос ожидает точного адреса и доступа.

## Стек и запуск
React + TypeScript + Vite, Node.js 24, встроенный node:sqlite. npm run dev запускает интерфейс (5173) и API (8787); /api проксируется Vite на сервер. npm run build и npm start раздают готовый dist вместе с API с порта 8787. Локальное SQLite-хранилище и серверный ключ находятся в игнорируемой .data. Настройки загружаются из необязательного .env; см. .env.example.

## Существующие компоненты команды
- src/core/model.ts: Scores { energy, clarity, support }, каждое значение — целое 1..5.
- Summary: { status: 'open' } | { status: 'insufficient' } | { status: 'published', means: Scores, needs: Array<keyof Scores> }.
- CheckinPanel() — прежний локальный демо-компонент Илиана.
- InsightsPanel({ summary }) — прежний демо-компонент Алисы.
- ActionsPanel({ summary }) — прежний демо-компонент Арины.
Имена экспортов и эти props сохранены. Модули ребят не менялись. Командный режим временно собран в src/core/TeamWorkspace.tsx — это работающий интеграционный пример, из которого можно постепенно вынести готовые компоненты по согласованию.

## Общий клиент
src/core/client.ts: api<T>(path, input?). Без input — GET, с input — POST JSON с X-VibeBot: 1. Cookies передаются same-origin. Таймаут 10 секунд; ApiError содержит status, code, message. Значения key/token никогда не писать в логи или коммиты.

src/core/contracts.ts: SessionSnapshot, Suggestion, TeamAction, FeedbackSummary, CheckinInput.
SessionSnapshot содержит только своё имя/роль, пространство, текущий round с допустимым Summary и собственным mySubmitted, доступные шаблонные предложения и общие договорённости. Списка голосовавших, числа текущих ответов и сырых ответов в нём нет.

## Реализованный API
Все пути начинаются с /api. Для изменяющих запросов нужен JSON и X-VibeBot: 1. Браузерный Origin проверяется. Ответы не кешируются.

| Метод и путь | Тело | Доступ / результат |
|---|---|---|
| GET /health | — | {ok:true} |
| POST /workspaces | {name, displayName} | Новое пространство и организатор; устанавливает cookie, возвращает SessionSnapshot |
| POST /join | {token, displayName} | Одноразовое приглашение; создаёт участника и сессию |
| POST /restore | {key} | Возвращает того же участника с теми же правами |
| GET /session | — | SessionSnapshot своей команды либо 401 |
| POST /logout | {} | Отзывает текущую сессию |
| POST /recovery-key | {} | Свой личный код входа на 30 дней; новый заменяет старый |
| POST /invitations | {} | Только организатор: {token, expiresAt}; одно использование, 24 часа |
| POST /checkins | {roundId, scores} | Сохранение/замена своего ответа в текущем открытом раунде |
| POST /rounds/close | {roundId} | Организатор: замораживает допустимый агрегат, удаляет отдельные ответы |
| POST /rounds/open | {} | Организатор: следующий раунд, если текущий закрыт |
| POST /actions | {roundId, suggestionId, goal} | Подтверждённый общий шаг; goal 1..500 символов |
| POST /actions/:id/feedback | {helpful:boolean} | Сохранение/замена своего отзыва |
| POST /actions/:id/close-feedback | {} | Организатор: замораживает допустимый агрегат и удаляет индивидуальные отзывы |

Изменения чек-инов, раундов, договорённостей и отзывов возвращают актуальный SessionSnapshot. Для приглашения и кода входа возвращается отдельный объект. Ошибки: {error:{code,message}} с HTTP 400/401/403/404/409/413/415/500. Конфликт roundId возвращает 409 STALE_ROUND, закрытый раунд — 409 ROUND_CLOSED.

## Приватность и ограничения
- Участник определяется сессией приглашения; при восстановлении личным кодом новый голос не создаётся.
- Организатор выдаёт отдельное приглашение человеку; реальная личность не удостоверяется.
- В таблице ответов используются HMAC-псевдонимы, отдельные для каждого раунда/действия. Прямого memberId в строке ответа нет; абсолютная анонимность от владельца сервера не обещается.
- После закрытия раунда/отзывов отдельные ответы удаляются, хранится только допустимый замороженный результат.
- Публикация после закрытия и минимум пяти отдельных ответов. Открытый и малый раунд не содержат средних значений и нужд.
- Низкая оценка — 1–2; доля >=40% запускает соответствующую подсказку. Это проверяемая стартовая гипотеза.
- Ключи сессий, приглашений и восстановления хранятся хешированными. Cookies HttpOnly/SameSite=Strict; для HTTPS выставить COOKIE_SECURE=true.
- Максимум два принятых шага за скользящие 24 часа, один вид шага за раунд. Для закрытого раунда выбираются максимум две нужды; при отсутствии опубликованных нужд доступно добровольное признание вклада.
- Сбор закрывает организатор; автоматического календарного расписания пока нет.
- Внешнее развёртывание, корпоративная авторизация, резервное восстановление и несколько экземпляров сервера пока не реализованы.

## ИИ

Подойдёт внешний API или готовая локальная модель через Ollama после выбора оборудования. Свободная автономия и обучение с нуля в критический путь не входят.
