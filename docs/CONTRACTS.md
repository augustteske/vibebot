# Контракты v0 — стартовый прототип
## Стек
React + TypeScript + Vite, Node.js 24, npm с lock-файлом. Точные версии в package-lock.json. Дополнительный сервер и хранение выбирает и реализует Август. Сейчас весь прототип — локальное интерактивное демо без сети и сохранения.

## Файлы и интерфейсы
- src/core/model.ts: Scores { energy, clarity, support }, каждое значение — целое 1..5.
- Summary — объединение { status: 'open' }, { status: 'insufficient' }, { status: 'published', means: Scores, needs: Array<keyof Scores> }.
- CheckinPanel() — экспорт без props, папка Илиана.
- InsightsPanel({ summary }) — экспорт с InsightsProps, папка Алисы.
- ActionsPanel({ summary }) — экспорт с ActionsProps, папка Арины.
- src/App.tsx — сборка компонентов и выбор демонстрационного сценария, владелец Август.
- src/demo/fixtures.ts — только вымышленные сценарии, владелец Алиса.

Менять сигнатуры по согласованию с Августом. Данные API проходят через отдельный клиент, который предоставляет Август, затем компоненты постепенно подключаются к нему. Пока API нет, все работают на имеющихся входах без блокировки.

## Правила продукта
- Раунд публикуется после закрытия и минимум пяти разных участников. Открытый и малый раунд не содержат средних значений или скрытых нужд.
- Низкая оценка — 1 или 2. Порог подсказки — доля низких ответов не менее 0.4 включительно.
- Повторная оценка участника до закрытия заменяет его предыдущую, не увеличивает участие.
- После закрытия ответы не меняются; следующий чек-ин относится к следующему раунду.
- Обратная связь о действии подчиняется отдельному такому же порогу агрегации.
- Общая публикация — после явного подтверждения. Время не ускоряется молча.
- Текущая aggregateRound считает строки демонстрационного массива, не доказывает уникальность реальных участников. Для реальной системы проверку уникальности, закрытия, прав и публикации делает сервер.

## Проектируемая серверная граница — реализует Август
Это план интеграции, не существующий API:
- Создание пространства/вход по приглашению и получение доступного контекста.
- Сохранение или замена собственного чек-ина в открытом раунде.
- Закрытие раунда организатором; выдача только допустимого Summary.
- Создание общей договорённости после подтверждения, изменение статуса.
- Сохранение собственного отзыва; выдача только разрешённого агрегата отзывов.
- Формирование текста подсказки из опубликованных общих показателей.
- Переформулирование явно переданного пользователем текста.

Сырые ответы, сопоставление автора с ответом, ключи модели и служебные секреты в клиент не возвращаются. Не отправлять реальные сообщения во внешний сервис без явного действия и понятного пользователю маршрута обработки.

## ИИ-решение
MVP: ограниченный workflow. Правила выявляют сигнал; один вызов модели формулирует подсказку или перефразирует сообщение; схема результата проверяется; человек подтверждает действие. Своего обучения и автономного цикла инструментов в критическом пути нет. Таймаут/ошибка/невалидный ответ → проверенный шаблон, с обозначением режима.

Провайдер заменяемый: внешний API либо локальная готовая модель через Ollama. Железо, доступный API и условия хакатона пока неизвестны, конкретная модель не выбрана. Локальность не означает автоматически полную приватность: учитывать сервер, логи и доступ.
