# QA-чек-лист Vibee: защита и демо

## Подготовка стенда

- [ ] Установлены Node.js 24 и Python 3.12.
- [ ] Из корня выполнены `npm install` и `python -m pip install -r bot/requirements.txt`.
- [ ] Для локальной проверки в PowerShell заданы `NODE_ENV=development`, `VIBEE_TELEGRAM_SYNTHETIC=true` и случайный `VIBEE_TELEGRAM_BOOTSTRAP_CREDENTIAL` (64 строчные hex-цифры); затем запущено `npm run dev`.
- [ ] В браузере открыт http://127.0.0.1:5173; сервер и Vite доступны на портах 8787 и 5173.
- [ ] Бот проверен командой `python -m bot --check`. Если демонстрируется личный polling, `TELEGRAM_BOT_TOKEN` задан только в локальном окружении и выполнен `python -m bot`.
- [ ] Перед показом проговорено: личный бот — отдельное демо, настоящее групповое подключение не включено.

## Проверки UI Telegram v1

- [ ] **Нет привязки:** войти в тестовое пространство без Telegram-привязки; блок показывает «Нет активной привязки» (`disconnected`), не нули и не метрики чек-инов.
- [ ] **Калибровка:** после пригодного закрытого периода, но до трёх пригодных дат, UI показывает «Идет калибровка» на чёрно-жёлтом фоне; чисел нет.
- [ ] **Недостаточно данных:** период с менее чем пятью авторами или 20 сообщениями не раскрывает метрики.
- [ ] **Опубликованный период:** опубликованные `outsideHoursPercent`, `participationEvenness`, `recognitionPercent` показаны как проценты; рядом показана шаблонная рекомендация с наблюдением, объяснением, ограничением и действием.
- [ ] **Визуализация графиков:** при статусе `published` отображаются круговая диаграмма сообщений вне рабочих часов и столбчатая диаграмма равномерности участия; при `calibrating` графики не отображаются, вместо них показана заглушка.
- [ ] **Состояния доступа:** `paused` показывает «Нет активной привязки»; ошибка API видна, не подменяется пустым успешным результатом.
- [ ] На узком экране 375px блоки и карточка читаемы, горизонтальной прокрутки нет.

### Проверяемый синтетический сценарий

Запустить из корня:

```sh
node --test --test-name-pattern="synthetic full cycle" tests/telegram-api.test.mjs
```

- [ ] Синтетическая привязка активируется только после согласия компании и всех участников.
- [ ] Приходят тестовые сообщения; период с 19 сообщениями остаётся `insufficient`.
- [ ] Два пригодных закрытых периода возвращают `calibrating`, без метрик.
- [ ] Третий период возвращает только агрегаты и `comparison: null`.
- [ ] Следом выдана рекомендация `source: template`; внешний ИИ не вызывается.
- [ ] Тест подтверждает шаг, закрывает обратную связь и проверяет паузу после отзыва согласия.

**Ограничение ручной проверки:** тест использует временную SQLite-базу и удаляет её при завершении. В веб-интерфейсе пока нет потока создания Telegram-привязки и загрузки такого тестового периода, поэтому опубликованные числа и карточка проверяются интеграционным тестом; для визуального QA в браузере нужна отдельно подготовленная синтетическая привязка. Не выдавать терминальный сценарий за настоящее сообщение из Telegram.

## Сохранённое демо чек-инов

- [ ] В режиме «Демо для питча» доступны три подписанных сценария с вымышленными данными.
- [ ] Открытый и малый раунд скрывают агрегаты.
- [ ] На опубликованном демо-сценарии видны три показателя чек-ина и объяснение подсказки.
- [ ] Действие не считается договорённостью до подтверждения; доступны «Позже», возврат, «Помогло» и «Не помогло».
- [ ] После обновления страницы демонстрационное состояние сбрасывается.
