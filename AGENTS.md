# Правила проекта Vibee

Основной репозиторий: https://github.com/augustteske/vibebot. Общая команда проекта — Shertwg group.

## Ветки и ревью
- `main` — проверенная демонстрационная версия; `develop` — интеграционная.
- Работайте в своей feature-ветке. Каждую законченную подзадачу оформляйте небольшим коммитом и pull request в `develop`.
- После слияния обновляйте свою ветку из ветки `develop` на GitHub, не переписывая чужую историю.
- Не отправляйте напрямую изменения в `main` или `develop`; не используйте force-push и не затирайте чужие изменения.
- Блокирующий вопрос фиксируйте в задаче с конкретным препятствием.

## Продукт и данные
- Telegram — основной вход, веб — кабинет; чек-ины остаются добровольным дополнением.
- Контракт Telegram и границы реализации описаны в [docs/CONTRACTS.md](docs/CONTRACTS.md). Не считать новые схемы реализованными, пока они не проверены кодом.
- Не обрабатывать тексты без полного согласия. Отказ, отзыв или неизвестный участник должны останавливать обработку всего чата.
- Реальные чек-ины и сообщения не коммитить; ключи не передавать в браузер.
- Руководитель видит только допустимые серверные агрегаты. Клиентская проверка в демо не обеспечивает приватность реальных данных.
- Не обещать полную анонимность, медицинскую оценку или измеренное улучшение без проверки.

## Границы модулей
- Общая основа и интеграция: `src/App.*`, `src/index.css`, `src/main.tsx`, `src/core/**`, `server/**`, `tests/**`, конфиги и скрипты.
- Чек-ин: `src/features/checkin/**`; Telegram-бот: `bot/**`.
- Рекомендации: `src/features/actions/**`; аналитика: `src/features/insights/**` и `src/demo/**`.
- Сохраняйте экспорты `CheckinPanel`, `ActionsPanel`, `InsightsPanel` и существующие props. Изменения общих контрактов согласовывайте с Shertwg group до интеграции.
- CSS компонента храните рядом с компонентом. Новые зависимости и общие настройки требуют согласования.
- Пока API не интегрирован, используйте существующие props и явно обозначенные синтетические данные.

## Готовность
- `npm test` и `npm run build` проходят; основной сценарий проверен вручную.
- В pull request описаны результат, проверки и ограничения; при изменении UI приложен скриншот.
- Демонстрационные данные обозначены как вымышленные. Не подключать реальные Telegram-сообщения без отдельного согласования условий согласия, хранения и отзыва.

## Технический стек
Node.js/React/SQLite сохраняются. Бот — Python 3.12/aiogram; новые модули и endpoint согласуются до реализации. Бот не пишет в БД напрямую. Корпоративный модуль требует согласия компании и каждого участника. Реальный Groq пока не подключён. Python-проверки: `python -m unittest discover -s bot/tests -v` и `python -m bot --check` из venv. Docker optional; не удалять volume с данными.
