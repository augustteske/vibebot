# Telegram-часть Vibee

## Текущий статус

- Сохранён личный демонстрационный чек-ин `/start` и `/stop` на aiogram.
- `bot/intake.py` отбрасывает пустой текст, правки, callback-и, нетекстовые события и сообщения от ботов. Ростер и согласия проверяет сервер.
- Telegram ID чата и отправителя берутся из update, а не из текста сообщения. Повторы локально подавляются.
- Автоматизированные тесты используют fake transport и локальный синтетический Node API; Telegram не вызывается.
- Intake умеет запрашивать статус привязки. При `STALE_REVISION` старый текст не пересылается под новой версией.
- `HttpTransport` повторяет сетевые ошибки, таймауты, 429 и 5xx не более трёх раз с тем же `eventId` в пределах 60 секунд. При неизвестном результате intake записывает только маркер паузы в `.data`, блокирует новые тексты и подтверждает серверный `transport_gap` после восстановления связи. Затем нужен явный серверный `resume` с новой revision; один ответ `active` не снимает блокировку.
- Каждый POST несёт заголовок `X-Request-Id` со свежим UUID — по нему сервер связывает записи в журналах; повторные попытки одного события используют тот же id.
- Подтверждённые `eventId` запоминаются в памяти на 24 часа: повтор того же события не уходит в сеть и получает ответ `duplicate`. Неизвестный результат доставки не запоминается, поэтому повтор с тем же `eventId` разрешён.
- Код не журналирует входящие события. Без `checkin_transport` личный чек-ин держит ответы только в памяти процесса до завершения или `/stop`: на диск и на сервер они не попадают. С настроенным `checkin_transport` три оценки после завершения отправляются на сервер и хранятся по серверной политике; организатору доступен только общий агрегат.
- `/clean` удаляет сообщения бота в личном чате за последние 48 часов. Telegram не позволяет ботам перечислять историю, поэтому бот помнит идентификаторы своих сообщений сам: в `VIBEBOT_DATA_DIR` лежит журнал `bot-clean-*.json` только с ID и временем отправки (не дольше 48 часов, без текста). Сообщения старше 48 часов и отправленные до появления журнала нужно удалить вручную; бот пишет об этом в ответе. Фотографии вопросов тоже попадают в журнал.
- `/lang ru` и `/lang en` переключают язык ответов; выбор хранится в `context.user_data` (aiogram `MemoryStorage`) и действует до перезапуска бота. Без команды язык — русский. `context.user_data` в памяти процесса: язык не пишется на диск и не переживает перезапуск.
- Перед каждым вопросом чек-ина бот отправляет картинку `bot/assets/questions/<ключ>.png`. Первый показ загружает файл в Telegram, дальше бот отправляет сохранённый `file_id`; кеш лежит в `VIBEBOT_DATA_DIR/bot-question-images-*.json`. Ошибка Telegram при отправке картинки не мешает задать вопрос: текст уходит в любом случае.
- Вопрос приходит одним сообщением: картинка, текст и кнопки оценок вместе — чат не копит по два сообщения на шаг. После ответа кнопки прошлого шага убираются, чтобы старые оценки не путали. Если картинку отправить не удалось, вопрос уходит обычным текстом с теми же кнопками.

## Язык и картинки вопросов

- Тексты — `bot/i18n.py`: словари RU и EN с плоскими ключами (`start.private`, `question.energy`). Русские строки исходные; английские лежат рядом. Неизвестный или пустой язык даёт русский.
- `/lang` без аргумента показывает текущий язык и кнопки «Русский / English»; кнопки работают и после перезапуска диалога, потому что язык лежит в состоянии пользователя.
- Меню команд Telegram общее для всех чатов, поэтому его подписи остаются русскими; ответы бота — на выбранном языке. Голосовой сценарий (`bot/voice.py`) пока отвечает по-русски.
- Картинки рисует `bot/tools/make_question_images.py` (Pillow, чистые фигуры без текста, 640×360). Перерисовать: `python -m bot.tools.make_question_images`. Новый вопрос — ключ в `QUESTION_KEYS` (`bot/flow.py`), строки `question.<ключ>` в `bot/i18n.py` и файл `bot/assets/questions/<ключ>.png`.
- Удалить кеш `file_id` можно, просто удалив `bot-question-images-*.json`: следующий показ загрузит файл заново.

## Ошибки сети

- `HttpTransport` перехватывает `httpx.TimeoutException` и `httpx.RequestError` и поднимает `TransportError` с полями `kind` (`timeout` / `network`) и `request_id` — тем же `X-Request-Id`, что ушёл в запросе. Текст сообщений в лог не попадает.
- В личном чате ошибка сети показывается по-человечески: «🐝 Упс, кажется, у нас проблемы с сетью. Мы уже чиним! Попробуйте позже.» и кнопка «Повторить». Она есть у завершённого чек-ина (оценки хранятся в памяти 5 минут, повтор идёт с тем же `nonce`) и у `/subscribe`.
- Повтор чек-ина после истечения 5 минут отвечает «Пройдите чек-ин заново: /start». Если сервер отклонил отправку (`PausedError`), кнопки нет: повтор не поможет.
- Групповой intake при сетевой ошибке молчит в чате (не засоряет рабочую группу), ставит паузу и пишет в лог тип ошибки и `requestId`.

## Офлайн-проверки

Установить зависимость из корня проекта (если её ещё нет), затем запустить:

```sh
python -m pip install -r bot/requirements.txt
python -m unittest discover -s bot/tests -v
python -m bot --check
```

`--check` загружает обработчики aiogram и не обращается к Telegram. Для самого личного демонстрационного polling-режима нужен `TELEGRAM_BOT_TOKEN`; не добавляйте его в репозиторий.

## Подготовка серверного транспорта

Обычный запуск `server/index.mjs` выключает Telegram-маршруты. Для локальной проверки задайте `VIBEE_TELEGRAM_SYNTHETIC=true` и `VIBEE_TELEGRAM_BOOTSTRAP_CREDENTIAL` (64 строчные hex-цифры) при `NODE_ENV=development`; этот API принимает только демонстрационные данные и не предназначен для реальных рабочих чатов. Связка личных аккаунтов и ролей для `/subscribe` проверяется сервером через scoped credential привязки.

Без настроенного scoped server transport личный демо-режим `python -m bot` с `TELEGRAM_BOT_TOKEN` работает отдельно и не передаёт сообщения в аналитику команды. Не подключайте к синтетическому режиму реальные рабочие группы или данные.

При работающем API на `http://localhost:8787` задайте переменные окружения:

```powershell
$env:TELEGRAM_BOT_TOKEN = "<токен Telegram>"
$env:VIBEE_BOT_TOKEN = "<токен bot API>"
$env:VIBEE_BINDING_ID = "<id привязки>"
$env:VIBEE_CHAT_ID = "<отрицательный ID группы>"
$env:VIBEE_API_BASE_URL = "http://localhost:8787"
python -m bot
```

Для scoped server transport обязательны `VIBEE_BOT_TOKEN`, `VIBEE_BINDING_ID` и `VIBEE_CHAT_ID`; базовый URL по умолчанию — `http://localhost:8787`. Для `/subscribe` команда обращается к API в личном чате и сервер сверяет Telegram ID с привязанным организатором. Не публикуйте токены. Для API вне localhost используйте HTTPS. Маркер транспортного сбоя хранится в `VIBEBOT_DATA_DIR` (по умолчанию `.data`) без текста и credential. После восстановления бот сначала подтверждает серверную паузу; сервер проверяет согласия при явном `resume`.

## Уведомления организатора

Организатор может включить личные уведомления командой `/subscribe`. Telegram-аккаунт должен быть заранее связан с участником-организатором в этой команде; сервер проверяет роль по привязке и не позволяет участникам подписаться от имени организатора. Команда работает в личном чате с ботом и при настроенном scoped bot transport.

На сервере задайте `TELEGRAM_BOT_TOKEN` (токен того же бота) для отправки сообщений через Telegram Bot API. Для polling-бота также нужны `VIBEE_BOT_TOKEN`, `VIBEE_BINDING_ID` и `VIBEE_CHAT_ID`, как описано выше. После закрытия периода бот отправляет организатору, который его закрыл, только опубликованные агрегированные метрики и текст рекомендации — не исходные сообщения. При выключенной синтетической интеграции или незаданном токене отправка не выполняется; закрытие периода остаётся успешным.

## Голосовые сообщения в активной группе

Голосовые сообщения обрабатываются только в активной привязанной группе/супергруппе, от обычного пользователя, не из пересылки и при наличии локальной квоты intake. Для включения задайте путь к уже установленной локальной модели Whisper:

```powershell
python -m pip install -r bot/requirements-voice.txt
$env:VIBEE_TRANSCRIPTION_MODEL_DIR = "<путь к локальной модели CTranslate2 с model.bin>"
```

`bot/voice_worker.py` проверяет Ogg/Opus, лимиты 2 МиБ/60 секунд и запускает Whisper офлайн в отдельном процессе; для группы серверная активная привязка служит проверкой согласий, а итоговый текст проходит обычный `TelegramIntake` (лимит, длина, дедупликация и серверная проверка отправителя). Аудио скачивается в ограниченный буфер памяти и не сохраняется в файл. Внешний API/модель автоматически не подключается и модель сама не загружается. Без корректно настроенной локальной модели расшифровка отключена.

## Ограничения

Личная расшифровка описана ниже и не включает групповую аналитику.

HTTP transport проверен на локальном синтетическом API, но фактическая доставка требует запущенных Telegram и Vibee API, проверенного состава и действующих секретов. Кэш дедупликации бота живёт только в памяти; сервер хранит ограниченные по времени ключи повторов. Личный демо-чек-ин сохранён.

## Личная расшифровка голосового

Отдельный opt-in режим: `/transcribe` → разрешение на одну запись → новое голосовое → текст в том же личном чате. Доступен при настроенной локальной модели. Групповые сообщения, пересланные записи, кружки и документы этот режим не обрабатывает. Результат не передаётся в API команды и не входит в метрики. Согласие `synthetic-media-v1` разрешает только метаданные и не включает расшифровку группового аудио.

Настройка из корня проекта (Windows PowerShell):

```powershell
& bot/.venv/Scripts/python.exe -m pip install -r bot/requirements-voice.txt
& bot/.venv/Scripts/python.exe -c "from faster_whisper.utils import download_model; download_model('tiny', output_dir='.data/models/whisper-tiny')"
$env:VIBEE_TRANSCRIPTION_MODEL_DIR = (Resolve-Path .data/models/whisper-tiny).Path
# TELEGRAM_BOT_TOKEN задаётся локально, не публикуйте его.
& bot/.venv/Scripts/python.exe -m bot
```

Для Linux используйте `bot/.venv/bin/python`. Веса скачиваются отдельно, без пользовательского аудио. Распознавание использует локальную модель `faster-whisper`, CPU/int8, русский язык. Во время обработки веса автоматически не скачиваются. Текущий Docker-образ бота не содержит optional-зависимостей и модели; инструкции выше предназначены для локального Python.

Лимиты: Ogg/Opus до 60 секунд и 2 МиБ; размер ограничен при скачивании, декодер проверяет контейнер, кодек и фактическую длительность. Одна задача на процесс бота без очереди; скачивание до 15 секунд, распознавание до 60 секунд. Согласие действует 5 минут на одну новую запись. `/stop`, истечение разрешения и остановка бота отменяют обработку; subprocess завершается, поздний ответ не выдаётся. При ошибке после скачивания нужно новое `/transcribe`; до скачивания можно исправить формат или дождаться свободного обработчика.

Аудио передаётся через память/pipe в отдельный процесс без токенов Telegram/Vibee. Приложение не записывает аудио или расшифровку в файлы, SQLite и журналы. Текст отправляется только в исходный личный чат и остаётся в Telegram; `/stop` не удаляет сообщения Telegram. Не присылайте чужую речь без разрешения. Распознавание может ошибаться; `tiny` — лёгкая стартовая модель, не обещание точности.

Проверки без Telegram и скачивания модели:

```powershell
& bot/.venv/Scripts/python.exe -m unittest bot.tests.test_voice -v
& bot/.venv/Scripts/python.exe -m bot --check
```

Источники API: [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [скачивание aiogram](https://docs.aiogram.dev/en/latest/api/download_file.html).
