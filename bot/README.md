# Telegram-часть Vibee

## Текущий статус

- Сохранён личный демонстрационный чек-ин `/start` и `/stop` на aiogram.
- `bot/intake.py` отбрасывает пустой текст, правки, callback-и, нетекстовые события и сообщения от ботов. Ростер и согласия проверяет сервер.
- Telegram ID чата и отправителя берутся из update, а не из текста сообщения. Повторы локально подавляются.
- Автоматизированные тесты используют fake transport; отдельные HTTP-тесты используют подставной клиент, без сети и токенов.
- Intake умеет запрашивать через транспорт статус привязки и сводку; при `STALE_REVISION` один раз получает актуальный статус и повторяет событие с новым `eventId`. Fake transport не обращается к серверу.
- Для реальной доставки добавлен `HttpTransport` на `httpx.AsyncClient`. В группах он берёт `chatId`/`senderId` только из Telegram update; ростер и согласия проверяет сервер. Ответ `403 FORBIDDEN` или `409 CONSENT_REQUIRED` ставит intake на локальную паузу.
- Код не журналирует входящие события. Демонстрационный чек-ин также не сохраняет ответы на диск или в сервер.

## Офлайн-проверки

Установить зависимость из корня проекта (если её ещё нет), затем запустить:

```sh
python -m pip install -r bot/requirements.txt
python -m unittest discover -s bot/tests -v
python -m bot --check
```

`--check` загружает обработчики aiogram и не обращается к Telegram. Для самого личного демонстрационного polling-режима нужен `TELEGRAM_BOT_TOKEN`; не добавляйте его в репозиторий.

## Подготовка серверного транспорта

Обычный запуск `server/index.mjs` пока выключает Telegram-маршруты; настройка переменных ниже сама по себе не включает доставку. Бот не реализует личную привязку, согласия и проверку состава. Реальный групповой чат пока не подключать. HTTP-клиент проверен только с подставным клиентом; серверный API — на синтетических данных. Авторизованного маршрута сводки для бота пока нет.

При работающем API на `http://localhost:8787` задайте переменные окружения:

```powershell
$env:TELEGRAM_BOT_TOKEN = "<токен Telegram>"
$env:VIBEE_BOT_TOKEN = "<токен bot API>"
$env:VIBEE_BINDING_ID = "<id привязки>"
$env:VIBEE_CHAT_ID = "<отрицательный ID группы>"
$env:VIBEE_API_BASE_URL = "http://localhost:8787"
python -m bot
```

Для будущего сетевого режима обязательны `VIBEE_BOT_TOKEN`, `VIBEE_BINDING_ID` и `VIBEE_CHAT_ID`; базовый URL по умолчанию — `http://localhost:8787`. Не публикуйте токены. Для API вне localhost используйте HTTPS. После ошибки доставки intake прекращает пересылку до перезапуска. Перед возобновлением нужно поставить серверную привязку на паузу с причиной transport_gap и повторно проверить согласия.

## Ограничения

HTTP transport подключён, но фактическая доставка требует запущенных Telegram и Vibee API и действующих секретов. Кэш дедупликации живёт только в памяти процесса; гарантированная доставка и сетевые повторы не реализованы. Личный демо-чек-ин сохранён.
