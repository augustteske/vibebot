# Тексты Telegram-профиля Vibee

Тон: спокойный, дружелюбный и ясный. Используйте эмодзи умеренно; не обещайте анализ реальных групп, работающие уведомления или доступную всем расшифровку.

## Название

```text
Vibee
```

## Короткое описание (About, до 120 символов)

```text
Чек-ин Vibee: три оценки о силах и ясности, голосовая — по согласию при настроенной модели. Без группового сбора.
```

## Описание бота (до 512 символов)

```text
Vibee — добровольный личный чек-ин: три оценки от 1 до 5 после согласия. В демо-режиме ответы остаются в памяти и никуда не передаются; передача в обезличенную сводку команды — только при отдельной серверной настройке, где Telegram ID проверяет участие. Черновик живёт до 5 минут; /stop очищает. Расшифровка одной новой голосовой — по согласию и при настроенной локальной модели: аудио и текст бот не сохраняет. Групповой сбор по умолчанию выключен. /start — сценарии, /help — справка, /privacy — данные.
```

## Список команд для BotFather

```text
start - Открыть меню сценариев
help - Доступные команды и сценарии
privacy - Как бот обрабатывает данные
stop - Отменить сценарий и очистить черновик
clean - Удалить сообщения бота в этом чате
transcribe - Согласие на одну голосовую (нужна локальная модель)
subscribe - Уведомления организатора (если настроены)
```

`/transcribe` зарегистрирована всегда, но без настроенной локальной модели отвечает, что расшифровка недоступна, и голосовое не скачивает. `/subscribe` работает только при настроенном scoped server transport, связанном Telegram-аккаунте организатора и включённой серверной доставке: сервер проверяет роль и сам решает, включены ли уведомления. Если условия не выполнены, бот сообщает об этом и не обещает доставку.

## Что подтверждено кодом

- Личный чек-ин без серверного транспорта: три оценки и согласие, черновик только в памяти, после завершения или `/stop` удаляется, на диск и в сервер ничего не пишется (`bot/flow.py`, `bot/__main__.py`).
- С подключённым транспортом завершённые оценки уходят на сервер (`HttpTransport.submit_personal_checkin`). Сервер проверяет по Telegram ID, что отправитель есть в ростере команды, хранит три оценки и хеш для защиты от повторов, без самого ID, а организатору показывает только агрегаты (`server/telegram-store.mjs`, `server/store.mjs`).
- Серверные Telegram-маршруты в обычном запуске выключены: передача чек-ина в сводку и групповой сбор работают только в отдельном синтетическом контуре, не с реальными рабочими чатами (`bot/README.md`, `server/telegram-store.mjs`).
- `/stop` отменяет личный чек-ин и согласие на расшифровку; сообщения в Telegram не удаляются (`bot/__main__.py`, `bot/voice.py`).
- `/clean` удаляет свои сообщения в личном чате за последние 48 часов, которые бот запомнил при отправке. Telegram не даёт ботам перечислять историю, поэтому более старые сообщения и сообщения, отправленные до запуска без журнала, остаются — бот предупреждает об этом. В журнале только идентификаторы и время, без текста (`bot/cleanup.py`).
- Расшифровка доступна только при заданном `VIBEE_TRANSCRIPTION_MODEL_DIR`; согласие выдаётся на одну новую голосовую, аудио и результат не пишутся в файл или БД (`bot/voice.py`).
- Групповой сбор выключен в обычном запуске: он требует scoped server transport, активной привязки и согласий (`bot/__main__.py`, `bot/intake.py`, `bot/README.md`).
- Синтетические тесты используют fake transport и локальный Node API, реальный Telegram не вызывается (`bot/README.md`).

## Ограничения длины

Официальная документация Telegram: `/setabouttext` — до 120 символов, `/setdescription` — до 512 символов (https://core.telegram.org/bots/features#botfather).
